# 미확인 항목 후속 점검

2026-11-06. 사용자는 실제 구매·환불·계정 간 격리·실제 기기 사용을 추후 직접 검증하기로 했습니다. 아래 자동 검사와 코드 검토를 실사용 검증으로 표시하지 않습니다.

## 코드 검토에서 발견·수정한 중요 문제

### 클라우드 응답 대기 중 로컬 편집 덮어쓰기

QuickBill·Stampbook·Stayline의 공통 동기화에서, 비어 있던 기기가 클라우드 읽기를 기다리는 동안 기록을 추가하면 응답 도착 후 새 기록이 사라질 수 있었습니다. 기존 코드에서 자동 동기화와 수동 클라우드 선택 모두 재현했습니다.

요청 시작 시점과 응답 시점의 로컬 스냅샷을 비교하고, 변경됐으면 원문을 유지한 채 충돌 상태로 멈추도록 수정했습니다. 기기에 클라우드 사본을 적용하는 데 실패하면 성공 메타데이터를 기록하지 않도록 고쳤습니다. 각 앱은 적용 성공·실패를 명시적으로 반환합니다.

합성 데이터와 지연된 응답을 사용한 회귀는 세 앱에서 각각 8개씩, 합계 24개입니다. 대기 중 편집·예외·명시적 실패·정상 적용을 자동 동기화와 수동 선택 양쪽에서 확인합니다. 실제 클라우드 계정이나 고객 데이터를 사용하지 않았습니다.

### WebKit의 좁은 파일 입력란

Quotanest 파일 입력의 기본 최소 폭 때문에 360px 화면에서 문서 폭이 390px로 넘치는 현상을 WebKit에서 재현했습니다. 파일 입력의 최소·최대 폭을 명시해 수정했습니다.

### 검사 도구의 CSP 오탐

일부 WebKit 스크린샷에서 Playwright의 애니메이션 동기화용 `body {}` 임시 스타일이 CSP에 차단되어 다음 화면의 오류로 기록되는 현상을 분리 재현했습니다. WebKit 자동 검사에서는 스크린샷을 생략해 임시 스타일 삽입을 피했습니다. 접근성·레이아웃·기능 검사와 CSP 오류 검출은 유지하며, 화면 캡처는 Chromium·Firefox로 수행합니다. 앱의 `style-src 'self'` 정책을 완화하지 않았습니다.

## 재현 방법과 판정 범위

각 저장소에서 `npm ci`, `npm run check`, 함수 번들이 있는 앱은 `npm run bundle`을 실행합니다. Playwright와 필요한 OS 종속성을 설치한 후 `BROWSER_ENGINE=firefox npm run test:browser`, `BROWSER_ENGINE=webkit npm run test:browser`로 반복할 수 있습니다. 기본값은 Chromium입니다.

엔진별 결과는 `artifacts/browser/<engine>/report.json`에 저장하며 엔진 이름·버전과 `realDevice:false`를 포함합니다. 좁은/넓은 화면, 밝은/어두운 테마, 영어/한국어(한국어 전용 앱 제외), 접근성과 앱별 가져오기·내보내기·복구 흐름을 검사합니다. 이 테스트는 외부 API를 대신하는 로컬 응답을 사용합니다. 모든 버튼의 실클립보드 동작을 검증했다고 해석하지 마세요.
